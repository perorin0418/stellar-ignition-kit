# ChangeSet README

## ChangeSet の位置づけ

ChangeSet は、本プロジェクトにおける **最下流の実装指示単位**である。

- 1 ChangeSet = 1 PR / 1 commit 相当
- Task を達成するための「具体的な変更操作」を定義する
- この ChangeSet 単体で **ビルド・テストが通る状態**を目指す

Task が「何を達成するか」を示すのに対し、  
ChangeSet は「どのファイルを、どう変更するか」を示す。

---

## ChangeSet に記載すべき情報

ChangeSet では、以下を **必ず具体的に**記載する。

- 変更対象ファイル
- 各ファイル内で行う作業の一覧
- 各作業の目的と変更内容
- 作業種別（Add / Modify / Delete）

抽象的な方針説明や設計意図は Task 側に記載し、  
ChangeSet では **操作レベルの指示**に限定する。

---

## 命名・構造ルール

### ChangeSet ファイル名
- changeset-<Vision No.>.<Milestone No.>.<Feature No.>.<Task No.>.<ChangeSet No.>-<簡潔な変更名>.md/
- changeset-1.2.3.4.5-AddAuthGuardRedirects.md
- changeset-6.7.8.9.10-UpdateNavigationShellLayout.md

- ChangeSet ID は Task から参照される前提とする

---

## 構造ルール

ChangeSet は、以下の構造に従って記述する。

1. ChangeSet 名
2. ID / 所属 Task
3. 変更対象
4. ファイル単位の作業一覧
5. 各作業の目的・変更内容

### ファイル単位でまとめる理由

- AI が変更範囲を正確に把握できる
- 人がレビュー時に差分を追いやすい
- 実装漏れ・重複変更を防げる

---

## 作業単位（番号付き項目）の考え方

各ファイル内の番号付き項目は、  
**そのファイルに対する独立した変更操作**を表す。

例:
- 処理の追加
- 既存処理の変更
- 関数・構造体の新規追加
- テストケースの追加・修正

番号は **実装順序ではなく、論理的な分解単位**を示す。

---

## 作業種別の定義

| 種別 | 意味 |
|----|----|
| Add | 新しいファイル、関数、処理の追加 |
| Modify | 既存コードの挙動変更・拡張 |
| Delete | 不要コード・処理の削除 |

※ 種別は必ず明示すること。

---

## 記述時の制約（重要）

ChangeSet では以下を禁止する。

- 「適切に」「必要に応じて」などの曖昧表現
- 設計方針の新規導入
- Task に記載されていない要件の追加
- 変更対象ファイルを曖昧にする記述

すべての変更は  
**ファイル名 + 具体的な作業内容**まで落とし込む。

---

## 非変更事項の扱い

ChangeSet に記載されていないものは  
**原則として変更しない**。

特に以下は暗黙に非変更対象とする。

- 公開 API のシグネチャ
- DB スキーマ
- 設定ファイル
- 他 Task の責務

変更が必要な場合は、別 ChangeSet として切り出す。

---

## 優先順位

実装判断に迷った場合の優先順位は以下の通り。

1. 90_guidelines（コーディング・実装規約）
2. 05_architecture
3. Task README
4. この ChangeSet

---

## AI / opencode 向け指示

- この ChangeSet の内容のみを根拠に実装を行うこと
- 曖昧な点がある場合は **勝手に補完せず停止する**
- 変更内容に記載されていない処理は実装しない
- ファイル一覧にないファイルは変更しない
