# Architecture (Authoritative)

## このディレクトリの位置づけ（最重要）

このディレクトリは、本プロジェクトにおける  
**システム構成・設計の正（Single Source of Truth）**を定義する。

ここに記載された内容は、
Vision / Milestone / Feature / Task よりも **優先度が高い**。

---

## 拘束力の宣言

- 本ディレクトリに記載された構成・設計は **事実として扱う**
- Feature や Task は、本ディレクトリの内容に **必ず従う**
- 実装上の都合による構成変更は **禁止**

構成を変更する必要が生じた場合は、
**本ディレクトリの資料を更新した上で**、
上位レイヤー（Vision / Milestone）との整合を取ること。

---

## このディレクトリに置くもの

以下は **正式な構成情報**としてここに配置する。

- システム全体構成
- コンポーネント構成
- データフロー
- デプロイ構成
- 通信方式・責務分離
- 永続化方式（DB / Storage）

---

## 置いてはいけないもの

以下は **他ディレクトリの責務**であり、ここには置かない。

- ビジネス要件・目的 → `00_vision.md`
- 機能仕様の詳細 → `20_features/`
- 実装手順・作業指示 → `30_tasks/`
- 一時的な検討メモ → `15_design-notes/`

---

## 図と文章の扱い方（重要）

- `.md` ファイルを **正とする**
- `.png` / `.svg` は補助資料
- 図だけで意味が完結してはいけない
- すべての図には **文章による説明**を必ず付ける

---

---

## AI / opencode 向け指示（明示）

- 実装・設計判断時は、本ディレクトリを **最優先で参照**すること
- 本ディレクトリの内容と Task が矛盾する場合、
  **Task を修正対象とする**
- 構成変更を提案する場合は、
  変更案を文章として提示し、人の承認を必要とする

---

## 変更ルール（厳守）

- 構成変更は軽微であっても必ず記録する
- 図と文章の不整合は禁止
- 履歴を消さず、変更理由を残す

---

## このディレクトリの目的（まとめ）

このディレクトリは、
**「AI が勝手に賢くならないための安全装置」**
であり、
**「人間と AI が同じ設計を見ている状態を保証する」**
ためのものである。
