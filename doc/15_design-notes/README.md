# Design Notes / Decision Records

## このディレクトリの目的

このディレクトリは、本プロジェクトにおける  
**設計上の判断・制約・トレードオフを記録するための補足資料群**である。

ここに記載された内容は、
Vision・Architecture・Feature を解釈する際の
**判断根拠および制約条件**として扱う。

---

## このディレクトリに置くもの

以下のような情報を配置する。

- 設計判断（Decision）とその理由
- 採用しなかった代替案と却下理由
- 技術的・組織的な制約
- 将来変更を想定した前提条件
- 一時的な妥協点（Known Trade-offs）

例：
- なぜこの技術を選んだのか
- なぜこの構成にしているのか
- なぜ「やらない」判断をしたのか

---

## 置いてはいけないもの

以下は **他ディレクトリの責務**であり、ここには置かない。

- 正式なシステム構成図 → `05_architecture/`
- 機能仕様の確定版 → `20_features/`
- 実装手順・作業指示 → `30_tasks/`

---

## 拘束力レベル（重要）

このディレクトリの情報は、以下の優先度で扱う。

1. **明示的な制約・禁止事項**  
   → 実装・設計時に必ず遵守すること
2. **設計判断の理由・背景**  
   → 代替案を検討する際の判断基準として参照する
3. **将来変更の余地に関する記述**  
   → 勝手に変更せず、人の判断を要する

※ 明示されていない限り、  
ここにある内容は **自動的に変更・最適化してよいものではない**。

---

## AI / opencode 向け指示

- Task 実装時に判断が必要になった場合、
  まず本ディレクトリを参照すること
- 本ディレクトリの記述と Feature / Task が矛盾する場合、
  **人に確認が必要な状態**と判断すること
- 設計を変更する場合は、
  変更理由を新たな design note として追記すること

## 想定ファイル構成
```
15_design-notes/
├─ README.md ← 本ファイル
├─ decisions.md ← 設計判断の記録
├─ constraints.md ← 技術・運用制約
├─ tradeoffs.md ← トレードオフ・妥協点
└─ assumptions.md ← 前提条件・仮定
```

---

## 更新ルール

- 設計判断を変更した場合は必ず記録を残す
- 既存の判断を削除せず、履歴として追記する
- Feature / Task 側での独断変更は禁止

このディレクトリは、
**設計の一貫性を守るための知識ベース**である。
