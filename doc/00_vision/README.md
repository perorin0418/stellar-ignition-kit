# Vision

## このディレクトリの位置づけ（最上位）

このディレクトリは、本プロジェクトにおける  
**目的・価値・成功条件を定義する最上位レイヤー**である。

ここに記載された内容は、
すべての Milestone / Feature / Task / Architecture に優先する。

---

## Vision の役割

Vision は、
- 何のために作るのか（Why）
- 何を達成すれば成功か（What）
を定義する。

Vision は **実装方法や構成を定義しない**。

---

## このディレクトリに置くもの

以下は **Vision として正式に扱う情報**である。

- プロジェクト概要
- 目的（Why）
- ゴール（What）
- 成功条件（Success Criteria）
- 非ゴール（やらないこと）
- 設計・実装上の基本方針
- 技術的前提・制約
- 対象 Milestones

---

## 置いてはいけないもの

以下は **他レイヤーの責務**であり、ここには置かない。

- システム構成・技術選定 → `05_architecture/`
- 計画・スケジュール → `10_milestones/`
- 機能仕様 → `20_features/`
- 実装内容 → `30_tasks/`
- 設計判断の理由 → `15_design-notes/`

---

## 拘束力レベル（重要）

Vision の記述は、以下の拘束力を持つ。

- **目的・成功条件**
  → すべての判断の最終基準
- **非ゴール**
  → 明示的な禁止事項
- **判断基準**
  → トレードオフ発生時の優先順位

Vision に反する実装は、
たとえ動作していても **不正解**とする。

---

## AI / opencode 向け指示

- 判断に迷った場合は必ず Vision に立ち戻ること
- Vision に記載されていない目的を追加しない
- Vision を再解釈・言い換え・最適化しない
- Vision に反する変更提案は **人の承認が必要**

---

## 想定ファイル構成

```
00_vision/
├─ README.md ← 本ファイル
└─ vision-<Vision No>.md ← Vision 本体
```

---

## 更新ルール

- Vision の変更は **プロジェクトの方向転換**を意味する
- Feature / Task の都合で変更してはならない
- 変更理由・影響範囲を必ず明記する

---

## まとめ

Vision は、
**「何を作るか」ではなく「なぜ作るか」を定義する層**である。

このディレクトリは、
人と AI が同じ目的を共有して作業するための
**最終的な共通理解の基盤**として扱う。
